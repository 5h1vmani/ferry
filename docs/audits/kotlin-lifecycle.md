# Audit: the phone app's engine object, lifecycle, and scan path

Date: 11 September 2026.
Scope: `FerryEngine.kt`, `FerryApplication.kt`, `MainActivity.kt`, `ReachableService.kt`, `Permissions.kt`, `QrScanner.kt`, `PairingScreen.kt`, `pairingStepOf` in `Mapping.kt`, and `AndroidManifest.xml`, at commit `63b0cbd`.
Method: I read every file in scope whole. I read the engine side in `crates/ferry-runtime/src/lib.rs` and `engine.rs` to check each claim. I ran nothing. Each row says whether I walked a complete path or not.
Findings: 15. Eleven are confirmed by reading a complete path. Four are plausible, and each names the step I could not confirm.

## Found safe

- A second `offerScanned` cannot reach the engine. ML Kit posts its success listener to the main thread by default. The `_scanSent` check and its write both run there, so no second call gets through. The comment at `QrScanner.kt:51` names the executor thread as the owner, which is not where the write happens, but the guard still holds.
- The camera stops when the scan screen is left. `onDispose` unbinds the provider on cancel, on a sent scan, and on a screen change.
- The camera permission itself survives activity recreation. `Permissions` holds process level flows, and `refresh` reads the real grant on every resume.
- Rotation alone does not stop the engine. `onDestroy` checks `isFinishing`, which is false for a configuration change.
- No listener callback touches a Compose object or an Android object. Every callback writes a `MutableStateFlow`, which accepts a write from any thread.
- A listener callback cannot deadlock against `stop`. No callback calls a `@Synchronized` method of `FerryEngine`.
- `create` cannot build two engines on one data directory in this process. The method is `@Synchronized` and returns early while `engine` is not null.
- The extra `startPairing(Code)` call from the `LaunchedEffect` at `PairingScreen.kt:103` changes no engine state. The engine refuses a second call while pairing runs, and reports the same state again.
- `forget`, `retry`, `retryBatch`, and `offerScanned` all run on `Dispatchers.IO`. The crate doc names those as the calls that block.
- The manifest declares the camera as a feature that is not required, so a phone with no camera can still install Ferry.

## Fix pass, 11 September 2026

Findings 2 through 15 are fixed, one commit per finding. Finding 1 is not fixed here: it is being fixed inside the engine by another builder, so this pass left every lock file alone.
