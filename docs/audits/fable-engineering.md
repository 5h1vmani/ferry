# Engineering audit, Fable

Date: 11 September 2026.
Commit: 3cd5451.
Scope: the Rust engine under `crates/`, the Mac app under `macos/Ferry/`, the phone app under `android/`, `scripts/`, and `.github/workflows/ci.yml`. Read only, on the main checkout.
Method: read the README, the contract, the agent-run rules, and the decisions. Then read the code by size. ## God files

`crates/ferry-runtime/src/engine.rs` is 3,748 lines with 54 `pub fn` and one `impl Engine` block from line 736 to 2200. The free functions after line 2326 hold five concerns: loading saved transfers and batches (2421-2584), presence and the accept loop (2584-2730), pairing in all its forms (2735-3282), serving a connection (3306-3487), and discovery with mDNS browsing and adb polling (3487-3694). A split by concern keeps `engine.rs` as the `Engine` struct and its public methods only, and moves the rest into `saved.rs`, `inbound.rs`, `pairing.rs`, `serve.rs`, and `discover.rs`, each taking `&Arc<Shared>` the way they already do. `dav/server.rs` at 1,851 lines holds the HTTP loop, `respond`, and one function per verb (`propfind` 1261, `put_file` 983, `move_verb` 759, `copy_verb` 841); one file per verb under `dav/` would match the `put.rs`, `lock.rs`, and `probes.rs` files that already exist. `access.rs` at 1,407 lines holds a wire format (285-495), a store (545-760), a roll-up (761-900), and 460 lines of tests; the format and the roll-up can each be a file.

## Over-built

- Three cargo target directories, finding 7. Cost: about three full workspace compiles per `gate.sh all` run and three copies of every dependency on disk.
- `crates/ferry-runtime/tests/engine_paths.rs` at 3,973 lines and `two_engines.rs` at 2,232 lines are the shared test files that `docs/agent-runs.md` rule 3 was written to stop. Cost: every merge that touches either file conflicts. Split by item, as the rule says, before the next batch.
- Nothing else read is beyond what a contract item asks for. Every engine module names its item in its first lines.

## Found sound

- Every file the engine writes has a version byte and a load path for the older version: `record.rs:48` (3), `batch.rs:46` (2), `held.rs:49` (2), `peers.rs:67` (2), `access.rs:82` (1), `auto_copy.rs:63` (1). Records and batches write a temp file, `sync_all`, then rename (`record.rs:309`, `batch.rs:180`).
- Every stored count has a bound: `MAX_PEERS` 64, `MAX_ROWS` 100,000 with compaction in `held.rs:55`, `MAX_ENTRIES_PER_DAY` 10,000 and 30-day retention in `access.rs:85-91`, `MAX_SPOOL_BYTES` and `MAX_PUT_BODY_LEN` in the DAV bridge, `MAX_HEAD_LEN` and `MAX_HEADERS` in `dav/http.rs:22-27`.
- The thread registry prunes finished handles on every `keep` (`engine.rs:404-411`) and refuses a handle once stopping is set, so long uptime does not grow it.
- Transfer workers are capped at `MAX_WORKERS` 4 with a 30 second backoff ceiling (`transfer.rs:76-85`).
- No test in `crates/` lacks an assertion. A script over every `#[test]` body found zero.
- The port, the pairing timeout, and every path bound live in one place each in Rust, and the apps read them through the bindings. No copy was found in Swift or Kotlin.
- Generated Swift and Kotlin bindings, the design tokens, and the error table are each checked against their source in CI and in `scripts/gate.sh gen`.
- `scripts/gate.sh` captures each step's own exit code without a pipe (`run_step`), so the exit code is never grep's. The Android gate runs `compileDebugKotlin`, which depends on `preBuild`, which depends on the cargo-ndk task (`android/app/build.gradle.kts:83-84`), so the Rust for the phone builds in the gate.
- `Cargo.lock` is committed and the toolchain is pinned to 1.92.0 in `rust-toolchain.toml`. `cargo audit` runs on every push.
- The app layers report every engine error instead of dropping it: each `catch` in `EngineModel.swift` calls `report` or sets `actionError`; each `catch` in `FerryEngine.kt` sets `_error`.
- Paths from a peer resolve through `cap_std::fs::Dir`, so a symlink cannot leave a root (`localfs.rs:11-18`).
